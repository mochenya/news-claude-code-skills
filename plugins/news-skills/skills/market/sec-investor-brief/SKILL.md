# SEC 公告投资简报

## 目标与定位

把 SEC 公告原始候选集加工成适合基金经理快速决策的短报告：

- 先查询、核验、去重，再写作；不把数据库中的全部条目机械搬进报告。
- 聚焦能改变盈利、现金流、估值、资本结构、行业竞争格局或中长期投资主题的公告。
- 报告只做事实整理和影响提炼，不做站队、不做情绪化判断、不提供买卖建议。
- 宁可少报，也不为凑数加入低信息增量公告。

## 触发与依赖

适用于：

- 最近 N 小时/天的 SEC 公告或公司公告；
- 周末合并查询、隔夜公告、近期美股公告；
- 8-K、业绩、指引、并购、融资、回购、资本结构、重大诉讼、AI/芯片/科技、能源资源及供应链事件；
- 用户说“筛掉没用的”“只看有价值的”“按投资视角总结”“推送 SEC 报告”等。

依赖并优先加载 `sec-reader-recent-summaries`，使用其只读查询入口。若进入新闻成稿阶段，同时遵循 `news-and-feeds` 的筛选与排版底线；本 Skill 对 SEC 投资报告的优先级更高。

## 工作流

### 1. 确认时间窗口

- 时间窗口由用户任务决定，不在本 Skill 中固定为 24 小时或 72 小时。
- 将窗口统一换算为北京时间（UTC+8）展示；查询仍按 sec-reader 的 `acceptance_datetime` 口径执行。
- 报告头部写出精确的开始时间、结束时间和时区。
- 保留半开区间 `[start, end)` 语义，明确区分 SEC 接收时间与摘要创建时间。
- 用户没有给出窗口时，不擅自套用固定窗口；沿用任务上下文，若仍无法确定再询问。

### 2. 只读查询

使用 `sec-reader-recent-summaries` 的脚本，命令形式为：

```bash
SKILL_DIR="/home/lht/tools/sec-reader-agent/skills/sec-reader-recent-summaries"
uv run --directory "${SKILL_DIR}" python scripts/sec_reader.py recent --hours <用户指定小时数>
```

可靠执行方式：先用终端将 JSON stdout 重定向到临时文件，再读取和解析文件。解析时读取顶层 `items`，同时记录 `count`、`pages` 和 `query`。

- `recent` 只返回已完成并持久化的摘要，不代表 SEC 在窗口内没有发布其他文件。
- 查询为空时，明确写“暂无已完成摘要”，不要自行推断需要刷新数据。
- 只有用户明确要求同步、刷新、发现或处理公告时，才运行 `sync-global`；普通查询不得擅自触发会写数据库、调用外部服务、调用模型或产生费用的处理流程。

### 3. 时间核验与候选集整理

- 逐条核验 `acceptance_datetime` 是否严格落在目标窗口内；窗口外、时间异常或时间无法确认的条目剔除。
- 以摘要内容为基础，但不要照抄原文；保留公司、股票代码、事件时间、金额、比例、指引和链接等关键事实。
- 同一事件的多个文件合并为一条，例如交易双方的 8-K、同一融资的发行文件与转售登记文件；元信息行并列保留相关 SEC 链接。
- 同一公司同一高管的分拆申报、重复 13G/13G-A 或同一事件的近似摘要，不重复占用条目。
- 若摘要存在 `human_review_required` 或其他不确定性标记，降低表达确定性，并在必要时标注“待核实”。

### 4. 投资价值筛选

优先保留以下内容，按直接影响和重要程度排序：

1. **业绩与现金流**：营收、利润、调整后 EBITDA、经营现金流、资产出售收益、全年指引及重大偏离。
2. **并购与战略变化**：交易完成、终止、重大融资安排、资产出售、品牌/业务控制权变化。
3. **资本结构与股东回报**：大额股权融资、债券/贷款、债务再融资、杠杆显著变化、重大回购和分红安排。
4. **AI、芯片、平台与科技产业**：会改变产能、订单、生态位、商业模式或竞争格局的事项；不因公司属于科技行业就自动纳入。
5. **能源、资源、电力与供应链**：重大资本开支、发电/输电能力、资源资产处置、长期需求指引及对产业链有明确影响的公司动作。
6. **重大法律、监管和治理事件**：可能改变估值折价、交易成败、经营许可或管理层执行力的事件。
7. **所有权与内部人交易**：只有在金额特别大、核心高管集中交易、交易方式异常或能提供明确判断增量时才纳入；普通 13G 被动持股、常规 4 表和 144 申报通常剔除。

通常输出 3-8 条核心公告；高价值内容少时进一步减少。不要因为条目数量少而补充董事任命、常规高管离任、普通投资者会议材料、重复持股披露或一般性注册文件。

每条入选公告都要回答：发生了什么、谁采取了动作、结果是什么、对盈利/现金流/估值/资本结构/产业链的直接影响是什么。可提示需要关注的变量，但不得写成主观投资建议。

### 5. 动态分类与排序

- 根据实际内容建立 2-5 个板块，不机械使用固定栏目。
- 重大并购、融资、业绩和资本开支主题优先置顶；板块内部按影响程度降序排列。
- 同一事件跨多个主题时只放一次，放在最能体现投资影响的板块。
- `潜在海外投资观察` 只能从本窗口内入选公告提炼；没有窗口内事实支撑时写“暂无明确线索”，不得用历史背景或市场常识填充。

## 固定排版格式

报告正文只输出成稿，不输出搜索、解析、筛选或推送过程说明。使用以下结构；板块数量和条目数量按实际结果变化：

```markdown
# 美国 SEC 公告筛选简报
📅 追踪区间：{北京时间开始时间} - {北京时间结束时间} (UTC+8)
📊 简报状态：从{候选总数}条已完成摘要中筛选{核心条数}条核心公告，并合并重复文件

---

{Emoji} **{动态板块标题}**

1️⃣ **{主体}+{动作}+{关键结果}**
{2-3句中文事实与直接影响，简洁、高密度，不超过约100字}
📅 {YYYY-MM-DD HH:mm} · 🔗 [来源简称](URL) | [来源简称](URL)

---

{其他动态板块及条目，沿用同一格式}

---

**潜在海外投资观察**：
- {仅基于本窗口内公告的主题线索、传导方向或需要跟踪的变量}
- {若没有足够事实支撑，写“暂无明确线索”}

**核心观察**：{2-4句，概括本窗口最重要的变化、共同信号和主要不确定性}
**生成时间**：{当前北京时间 YYYY-MM-DD HH:mm UTC+8}
```

排版约束：

- 全程中文，机构、人名、职位和业务名称优先使用中文；必要时中文后保留英文缩写、股票代码或公司正式名称。
- 每条概述后必须紧跟元信息行；时间统一为北京时间；来源使用 Markdown 链接，禁止裸 URL。
- 标题直接写主体、动作和结果，删除空泛表述；概述先事实、后影响，不大段引用公告。
- 重要程度排序，不按 SEC 接收顺序机械排列。
- 条目编号连续，Emoji 不得重复或跳号；写入文件后回读检查中文、Emoji、链接和编号是否损坏。
- 不预先把 MarkdownV2 特殊字符全部转义；若用 `hermes send` 投递，交给发送端处理，避免二次转义。

## 投递

若用户提供 Telegram、Discord 或其他投递目标：

1. 先生成并回读最终 Markdown 文件，确认格式和内容完整。
2. 使用对应平台的发送入口投递；Telegram 话题目标使用 `telegram:<chat_id>:<thread_id>`。
3. 发送后核验命令返回的成功状态、平台、目标和 message_id，再向用户报告。
4. 报告投递失败时如实说明，不把“已生成”说成“已发送”。

## 结束前检查

- [ ] 时间窗口与时区准确，所有条目在窗口内
- [ ] 已去重、合并、剔除低价值公告
- [ ] 每条都具备明确的信息增量或投资影响
- [ ] 没有把一次性收益、被动持股或常规人事变动写成重大信号
- [ ] 每条都有北京时间和 Markdown 来源链接
- [ ] 投资观察只基于窗口内事实
- [ ] 报告为中文、简洁、无情绪化判断、无投资建议
- [ ] 文件回读通过；如需投递，已核验真实发送结果
