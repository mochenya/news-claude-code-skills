# 日韩公司公告快讯排版模板

## 目标

输出适合快速扫读的公司公告快讯。保持短、清楚、可追溯：先说明发生了什么，再集中梳理本时段最值得看、可能有什么影响、后续需要核对什么。

## 固定模板

只使用一级标题和二级标题。Emoji 只出现在标题中，不在公告条目内堆叠图标，不使用三级标题、表格或卡片式字段。

```markdown
# 🇯🇵🇰🇷 日韩公司公告快讯

时间窗口：{YYYY-MM-DD HH:mm}—{YYYY-MM-DD HH:mm}（北京时间）

## 🇯🇵 日本

1. **{中文通用名或候选 display_name_hint；无 hint 时写暂无标准译名}（{股票代码或代码未提供}，{候选 display_name_hint 或暂无标准英文名}）｜{中文核心事项}**
   {一句话说明来源明确的公告事实；金额、数量、期限只有在来源中明确出现时才写。}
   {北京时间 HH:mm}｜[{中文来源简称}]({URL})

2. **{中文通用名或英文标准名}（{股票代码或代码未提供}，{英文/罗马字}）｜{中文核心事项}**
   {一句话说明公告事实。}
   {北京时间 HH:mm}｜[{中文来源简称}]({URL})

## 🇰🇷 韩国

1. **{中文通用名或候选 display_name_hint；无 hint 时写暂无标准译名}（{股票代码或代码未提供}，{候选 display_name_hint 或暂无标准英文名}）｜{中文核心事项}**
   {一句话说明公告事实；必要时补充可能影响或尚待确认的信息。}
   {北京时间 HH:mm}｜[{中文来源简称}]({URL})

## 🔎 本时段值得关注

- **{主题一}：** {本窗口公告反映的关键信号及其可能影响。}
- **{主题二}：** {第二个值得跟踪的盈利、产业、资本或风险变化。}
- **后续跟踪：** {正式公告、金额、时间表、管理层说明或下一批披露中需要核对的事项。}
```

## 条目规则

- 标题固定为「中文通用名或英文标准名（代码，英文/罗马字）｜中文核心事项」；原始日文、韩文、法人后缀和原文公告类型不得出现在可见正文。
- 没有稳定中文译名时，只能使用候选 JSON 的 `display_name_hint`；没有 hint 时写「暂无标准译名（代码，暂无标准英文名）」；不得使用日文假名、韩文字符、自行罗马化或自造中文音译。
- 股票代码只有原始数据明确提供时才可写；缺失时写「代码未提供」，不得猜测。
- 每条原则上只有「标题 + 一句话正文 + 时间来源行」。
- 每条必须附北京时间和 Markdown 来源链接，来源标签使用中文简称，禁止裸链接。
- 同一底层事件只保留一条。母公司、子公司、实际承建方分别披露同一合同，必须合并并在正文说明关系；同一公开收购、回购、增资或附件披露同理。
- 只有合同类型而没有标的、金额、对手方、期限或其他可识别事实的泛化合同标题，不进入正文。
- 只有泛化“子公司主要事项”、无具体内容的传闻澄清、例行 ETF 或基金披露、普通月度销售和一般宣传不进入正文。
- 日本、韩国分别编号；区内按重要性排序，不按发布时间或来源机械排序。
- 全文可见正文必须为中文；英文公司名、英文简称、罗马字、证券代码和 URL 可以保留。

## 长度与数量

- 正文硬上限为 3500 个字符，不得依赖发送层拆分或截断。
- 最多 10 条公告，日本和韩国各最多 6 条。
- 超出上限时按“业绩/重大订单/资本运作/控制权与风险/重点产业信号”的顺序保留，删除低优先级项目并压缩句子。

## “本时段值得关注”规则

通常写 1—3 条，集中回答：

1. 哪些公告最值得看；
2. 可能影响盈利预期、资本结构、产业链或风险判断的什么部分；
3. 下一步需要核对什么。

只能使用本时间窗口内公告作为事实依据，不用旧闻或行业背景补足。使用“可能、或将、需观察、尚待确认”等审慎表达，不强行判定利好或利空，不做投资建议。

## 空结果模板

某一市场无合格公告时仍保留该市场二级标题，并写：

```markdown
本时段暂无值得单列的重要公告。
```

两个市场均无合格公告时，末尾写：

```markdown
## 🔎 本时段值得关注

暂无明确新增信号。
```

## 输出检查

- 只出现一级、二级标题；
- Emoji 只出现在标题；
- 每条均有中文公司名或英文标准名、代码状态、中文核心事项、北京时间和 Markdown 来源链接；
- 不含日文假名、韩文字符、日文或韩文原文句子；
- 同一底层事件没有母子公司重复条目；
- 没有泛化披露、无内容传闻澄清或例行噪音；
- 正文不超过 3500 个字符，公告总数不超过 10 条；
- 总结只基于本窗口事实，没有把可能影响写成确定结论；
- 最终只输出简报正文，不输出采集、筛选、工具调用、修复或发送过程。
