# 日韩上市公司公告快讯

## When to Use

Use this workflow for intraday or scheduled incremental Japan/Korea listed-company announcement updates, including Kabutan, NAVER disclosure summaries, DART filings, company disclosures, and cron-delivered flash briefs.

## 目标与定位

把日本和韩国上市公司的新增公告整理成适合基金经理快速扫读的中文增量快讯：先说明哪家公司发生了什么，再集中梳理本时段最值得关注的信号、可能影响和后续验证点。

本 Skill 负责原始数据核验、时间窗口检查、事件级去重、价值筛选、中文提炼和最终排版。它不是完整行情报告，也不负责编造股价、成交量或估值数据。

## 适用输入与采集

先加载并遵循 `japan-korea-market-summary-retrieval`。定时任务由外层脚本预先采集原始 JSON，并运行候选预筛脚本生成候选 JSON；生成阶段只读取候选文件，不自行扩大时间窗口，不从搜索结果补充新的公告。候选预筛只负责提高召回效率，不能代替最终重要性判断和事件级去重。

默认采集命令：

```bash
node /home/lht/.hermes/profiles/global-politics-reporter/skills/research/japan-korea-market-summary-retrieval/scripts/japan-korea-summary-fetch.mjs \
  --source kabutan_alert,kabutan_earnings,kabutan_disclosures,naver_disclosure_summary,dart_recent_disclosures \
  --since "<START_ISO8601>" \
  --until "<END_ISO8601>" \
  --format json
```

不要在生产任务中使用固定页数限制，采集器应持续翻页至早于窗口起点。时间窗口统一使用北京时间 UTC+8，并采用 `[since, until)`：包含起点，不包含终点。先按时间字段核验每条记录，再开始筛选和写作。不得把窗口外项目放入正文或末尾总结。

若原始 JSON 无法解析、来源全部失败、窗口字段缺失或记录时间无法核验，任务应失败，不得把技术失败写成“暂无公告”。

相邻批次应使用连续、不重叠窗口。重复执行同一批次时，结果保持同一窗口口径；跨来源的同一事件只写一条，合并来源链接。

## 筛选、去噪与排序

只保留具有信息增量、盈利影响、产业信号、资本结构变化或风险变化的公告。宁可少列，不为凑数降低门槛。区内按重要性排序，不按来源或发布时间机械排序。

优先级：

1. 业绩预告、业绩修正、利润指引、重大订单和核心业务变化；
2. 回购、注销、分红显著调整、增发、配股、可转债、并购重组、公开收购和资产出售；
3. 主要股东或控制权变化、重大诉讼、监管调查、处罚、财务重述和退市风险；
4. 半导体、AI、汽车、电池、造船、金融、能源等重点产业中的有效经营信号。

直接剔除：

- ETF、基金或资产管理产品的日常披露、重复性净值或例行决算资料；
- 普通治理报告、例行 IR 活动、普通股东福利、常规月度销售和一般产品宣传；
- 没有新增事实的更正稿、重复转载和同一事项的多份附件；
- 只有“子公司主要经营事项”而未说明事项内容的泛化披露；
- 只有传闻或澄清标题、但未说明传闻对象、公司结论或实际变化的记录；
- 只有合同类型、没有标的、金额、对手方、期限或其他可识别事实的泛化合同标题；
- 小额且没有明确盈利、资本、产业或风险影响的交易。

### 事件级去重

去重单位是“底层事件”，不是公司或公告条数。以下情况必须合并为一条：

- 同一合同由母公司、上市子公司、实际承建方或经营主体分别披露；
- 同一公开收购、并购、资产出售或控制权变化涉及多家公司；
- 同一回购、增资、债券或资本政策由公告、编辑摘要和附件重复呈现；
- 同一事项的日文、韩文、英文版本或官方索引与编辑摘要重复出现。

判断是否同一事件时比较动作、标的、对手方、金额、数量、交付期和公告时间，而不是只比较公司名。合并后标题只写最能代表事件的公司；正文可说明母公司、子公司和实际执行主体的关系。只有在底层事项、标的或影响确实不同的情况下，才分别列出同一集团公司的公告。

## 事实与影响边界

- 只写原始 JSON、正式公告或已附来源明确支持的事实；定时任务不得用搜索结果替代原始来源；
- 金额、数量、期限、业绩数字、对手方和产品名称必须能在来源中核对，不能凭公司常识补齐；
- DART 只有泛化索引而没有具体内容时，不能从标题推断金额、合同对象或业务影响；信息不足就剔除；
- 可以说明可能影响，但必须使用“可能、或将、需观察、尚待确认”等审慎表达；
- 不把公告直接称为利好或利空，不做投资建议；
- 同一事件多源重复时优先保留官方链接，再附一个编辑摘要或新闻来源；来源不足时不强行补写。

## 中文硬约束

最终简报的可见正文必须全部使用中文。禁止直接复制日文或韩文标题、公司原文、公告类型和正文；禁止出现日文假名或韩文字符。公司英文名、英文简称、罗马字和证券代码可以保留，但来源标签、事项名称、事实正文和总结必须中文。

公司名规则：

- 优先使用中文财经媒体通用译名，不直译全称，不加法人后缀；
- 没有稳定中文译名时，只能使用候选数据提供的 `display_name_hint` 作为官方英文名或可核验的拉丁字母名称；没有 hint 时统一写「暂无标准译名（代码，暂无标准英文名）」，不得根据日文假名或韩文自行转写，不得自造中文音译；
- 标题格式为「中文通用名或英文标准名（代码，英文/罗马字）｜中文核心事项」；
- 同一公司、同一窗口内名称必须一致；
- 股票代码只有原始数据提供时才可使用，缺失时写“代码未提供”，不得猜测；
- 来源行使用中文简称，例如“DART公告”“NAVER公告摘要”“Kabutan适时开示”，不得保留来源原文标签。

## 排版与长度

读取并严格遵循本 Skill 附带的 `references/output-format.md`。它是唯一的排版模板。

单条只保留“标题 + 一句话事实 + 时间来源行”。最终正文硬上限为 3500 个字符，最多 10 条公告；日本、韩国分别编号，每个市场最多 6 条。超出上限时继续删减低优先级项目或压缩句子，不能拆成多条消息，也不能通过发送层截断。

## 生成前与发送前检查

生成前必须确认：

1. 已实际读取 `japan-korea-market-summary-retrieval` 的原始 JSON；
2. `since`、`until` 和北京时间窗口一致，所有条目严格在 `[since, until)` 内；
3. 已完成跨来源、跨公司和母子公司事件级去重；
4. 每条均有公司名、代码状态、中文核心事项、北京时间和 Markdown 来源链接；
5. 已删除低信息量公告、泛化披露和无实质内容的传闻澄清；
6. 金额、数量、期限和影响均有来源依据，没有把猜测写成事实；
7. 全文没有日文假名、韩文字符或混合原文句子；
8. 只使用一级、二级标题，Emoji 只出现在标题中；
9. 正文不超过 3500 个字符，公告总数不超过 10 条；
10. 末尾总结只提炼本窗口事实，并使用审慎措辞；
11. 最终只输出简报正文，不输出采集、筛选、工具调用、修复或发送过程说明。

外层脚本还必须在发送前执行机器校验；校验失败时不得发送，应先限次修订正文。模型不在 prompt 内直接调用发送命令。
